# 剪辑与时间轴护栏

需要删除静音、口头语、重复或其他片段时读取本文件。

## 目录

1. 候选不等于批准
2. Whisper token 清洗
3. 剪切边界与 EDL
4. CFR/VFR 与编码
5. 字幕重映射
6. 验收清单

## 1. 候选不等于批准

- `long_silence`：在口播中常可剪，但在采访、演示、剧情、音乐、冥想或动作等待中可能有意义。
- `filler_word`：孤立的“嗯/啊/um/uh”等可能是应答、犹豫、强调或轮次信号；结合上下文确认。
- `repeat_candidate`：永远高风险。叠字、术语、修辞、强调和真正口吃表面相同，不自动剪。
- 片头片尾：脚本只能识别静音，不能判断设备调试、花絮、片尾停留是否应保留。
- 多人重叠、笑声、掌声、呼吸、音乐起落和操作音附近不要只靠文字 token 决策。

把候选表提供给用户，包含时间范围、候选类型、文本、前后文和建议。只有明确批准的项进入
`approved_cuts.json`。

## 2. Whisper token 清洗

whisper.cpp JSON 可能包含 `[_TT_100]`、`[_BEG_]` 等内部 token。使用完整正则过滤：

```python
if re.match(r'^\[_.*\]$', text.strip()):
    continue
```

不要用 `endswith("_]")`；`[_TT_100]` 并不以 `_]` 结尾。漏过滤会破坏静音检测和文字对齐。

检测片尾静音必须把媒体总时长传给 `find_edit_candidates.py`。转录 JSON 本身不知道录制停止时间。

## 3. 剪切边界与 EDL

`build_edl.py` 只给 `long_silence` 两侧保留最多 0.3 秒呼吸间隔；`filler_word` 不加 padding，
否则短口头语只剪掉中间几十毫秒，音频仍在而字幕已删除。

生成 EDL 后检查：

- 区间在 `[0, duration]` 内、起点小于终点、重叠区间已合并。
- 保留区间非空；整段被覆盖必须报错。
- 总剪切时长与候选批准表一致。
- 每个边界不截断音节、动作、掌声或音乐节拍。

## 4. CFR/VFR 与编码

`select + setpts=N/FRAME_RATE/TB` 适合明确的恒定帧率输出，会把结果规范成 CFR。先用 ffprobe
比较 `r_frame_rate`、`avg_frame_rate` 和时间基；明显 VFR 或要求保留原节奏时，优先使用每段
`trim/atrim` 后 `setpts/asetpts`，再通过 `concat` 拼接，或先明确规范到目标 CFR。

剪切点通常不在关键帧上，必须重新编码，不能 `-c copy`。输出永远使用新文件名。编码结束后用
ffprobe 校验时长和音视频流，并抽查所有剪切边界。

## 5. 字幕重映射

`retime_srt.py` 使用 `keep_segments.json` 把旧时间轴映射到累计保留时长。注意：

- 先把总毫秒四舍五入，再拆分时分秒毫秒，避免非法 `,1000`。
- 完全落在删除区间的字幕条应删除；跨边界字幕需要试听，必要时手工拆条。
- `retime_srt.py` 不修改字幕文字。剪掉的口头语若与正文共处一条字幕，必须同步删字。
- 后续画面抽帧和字幕比对必须使用与最终 SRT 相同的时间轴；剪辑后字幕只能对剪辑后视频抽帧。
- 若合并剪辑和烧字幕，滤镜顺序必须为剪辑/重建时间轴在前，字幕在后。

## 6. 验收清单

逐点检查高风险剪辑，并至少抽查：

- 开头、25%、50%、75%、结尾的音画和字幕同步。
- 每个删除点后的第一条字幕是否提前或滞后。
- 口头语音频与字幕是否同时消失。
- 静音剪切是否保留自然呼吸，演示动作是否完整。
- 成片时长是否约等于原时长减去批准剪切时长；允许编码量化带来的小误差。
